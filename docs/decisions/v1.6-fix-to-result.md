## 2. Rules that hold for every item

1. **PrivacyCheck is the single source of truth for points.** Actions, Biggest wins, snackbars and chips read the deduction the scan produced (`PrivacyIssue.pointDeduction`, which comes from `PrivacyCheck` via `cappedDeductionFor` or the checker's tiered value). No second points table. The one partial value (Private DNS) is derived from the enum, not typed again (section 4.3).
2. **Hard rule:** no Action, Quick Win, recommendation or button suggests disabling or uninstalling Play Services or any app that came with the phone (`isSystemApp`). On GrapheneOS and other ROMs the Google apps are user apps and keep their uninstall advice.
3. **The score never depends on the current network.** Private DNS is judged by the setting. (The VPN check is by nature "is a VPN connected"; Oliver's call 4.)
4. **No new permission, no network, no Room schema change.** `PrivacyDatabase` stays at version 1. One new SharedPreferences file in section 4.8; that run is risky code.
5. **Copy:** strings.xml voice: direct, short, no exclamation marks, en dash for ranges, real minus sign (−) as in `fmt_deduction_chip`, "pts" with a space (`+5 pts`).

## 3. Words used below

- **Action** = a Quick Win tile in Actions (the existing `QuickWin`). The section keeps its name "Quick Wins" (Oliver's call 13).
- **Fix deep link** = a button that opens a Settings page to change something that is scored. It sets the rescan-on-return flag.
- **User scan** = a scan the user asked for: return from a fix deep link, Check again, the top-bar rescan, pull to refresh, Mark as done, Ad ID confirm or reset. Not: app start, widget alarm, boot, nightly safety-net scan.

### 4.4 M7 — the change label under the score, same words on the widget — M (v1.6.1, run 8)

Until run 8 ships, v1.6 keeps today's display unchanged: "Privacy Change ↑N pts" inside Device Information and "↑N" on the widget, each with its own show rule (section 1, M7 row). Nothing in v1.6 may write "today" next to the number.

**The choice: "today".** Both places already show the same number, `currentScore − dailyBaselineScore` (`ScoreHistory.kt:29-30`), where the baseline is the last score recorded before today's first scan (`ScoreHistoryRepository.kt:70-90`). The first scan after midnight resets it (`docs/decisions/widget-centre-change.md` §1). So the number *is* "change today". The 48 h value is only the widget's stale guard for when no scan happens at all; it never lets a change live longer than the next day's first scan.
